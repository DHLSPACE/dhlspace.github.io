# 本地工作台升级 · 2026-09-17

## 架构与使用

以用户本次明确说明为准：本机运行，GitHub 做版本同步和备份。参考文档里“必须再次询问部署形态”和云端采集的旧假设不作为本次要求。继续使用 Python 标准库服务器及 SQLite，启动方式不变，无新增运行依赖。

双击 `启动助手.cmd`，打开 `http://127.0.0.1:8765/`。默认“监控来源 / 更新聚焦”只列未读新增、修改等事件；首次建档、抓取失败不冒充新公告。视图和主题选择会记忆。

- 添加：输入校名搜索，或粘贴网址。门户先选栏目；试抓成功后核对标题、日期、链接，再确认入库。预览有效期15分钟，改网址或用途必须重新试抓。
- 持久化：添加、编辑、暂停、置顶写入 SQLite 和 `sources/custom.json`。规则为 JSON 描述的 DOM 路径，采集器使用同一规则。写文件失败回滚。重启恢复配置，保留原有历史。
- 分类：学校、来源类型、信息类别、状态组合筛选。信息类别按标题粗分，可在“通知与变更 / 已发现的全部通知”纠正；来源本身也可设置分类。
- 展示：更新聚焦、学校分组（可折叠）、紧凑列表。支持更新优先、最近检查、学校名、添加顺序排序；置顶优先。
- 外观：浅色、暗色、跟随系统；侧栏折叠保留图标；玻璃模糊主要用于侧栏和弹窗，列表卡片不叠加大量模糊。
- 定时：沿用 Windows 计划任务，电脑须开机、联网并满足登录条件。GitHub 工作流已在本地改为仅构建/部署，删除定时采集步骤。

## 搜索与识别边界

校名搜索默认尝试 Bing 公开搜索结果；本轮实测其 robots 禁止自动读取，不能宣称任意学校联网搜索已跑通。因此已接入正式的 **Brave Search API**：在“设置与帮助 → 联网校名搜索”填自己的密钥，即可通过 API 搜索其他学校。密钥只存本地数据库，不回传到页面、不进入导出与 Git 同步。申请入口：https://api-dashboard.search.brave.com/ ，接口依据：https://api-dashboard.search.brave.com/app/documentation/web-search/get-started 。本轮没有用户密钥，API 仅完成请求分派与模拟响应测试，尚未实测账号调用。

搜索结果和已整理入口分开标注，失败保留原因与浏览器搜索链接。已整理学校可直接选择候选试抓。通用解析不能覆盖所有高校页面；未知动态页面暂时拒绝加入。本轮没有实现浏览器渲染采集，因为没有证据证明当前失败由 JS 渲染造成。

列表试抓通过不等于所有未来页面、正文和附件都能抓取。登录或验证码页面继续手动保存。首次正式采集建立历史基线，不把旧通知标成今天发布。

## Git 同步与备份

设置中点击“准备同步文件”，或执行 `python -B sync_local.py`，将代码、来源配置、结构化笔记、通知、事件和归档索引复制到旁边 Git 仓库 `sch-doc-local/`。

包含个人录入的笔记，可在提交前检查 `sync/records.json`。准备操作不调用 Git 提交或推送，也不自动公开到网站。

- `sources/custom.json` 为来源配置，`catalog.json` 仅为候选。
- `sync/records.json` 为结构化备份，不含代理设置。新机器首次启动且数据库为空时恢复来源、通知、事件、笔记。
- SQLite、原始 HTML/PDF/Office、手工材料、日志和测试依赖排除在 Git 之外。索引不等于原件；新机器不把缺失文件的索引显示成已成功归档，需另行复制原 `data/` 或重新采集。
- 已有数据库时不覆盖导入旧同步数据；尚未实现多台机器双向数据库合并。

本地工作台是主入口。现有 `/sch-doc/` 公网站点保留历史公开资料，只修正旧的云端定时说明。尚未提交、推送或发布此次更改，远端站点和工作流不会因本地文件修改而自动改变。
