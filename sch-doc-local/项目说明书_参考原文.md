# 研招信息监控助手 — 项目说明书

> 本文档写给 Codex（或其他编程 agent）直接执行。目标：产出一个能在我本地电脑运行的、
> 带浏览器界面的小工具，用于监控保研/考研相关网页更新、归档历史信息、并结构化记录我
> 自己整理的笔记。

---

## 0. 我是谁 / 为什么做这个

我是南昌大学化学工程与工艺专业大三学生，目标是保研或考研到化工相关方向的硕士。
现在（大三上）正是各高校发布 2027 年推免/考研相关信息的窗口期，这些信息：

- **时效性强**：公示期通常只有 3-7 天，过时页面会被覆盖或下线，需要抓紧存档；
- **分散在多个学校/学院的官网通知列表页**，没有统一入口；
- **我需要长期、跨年份追踪**（如历年推免名额变化），单次记录没有意义，要靠日积月累。

我不太会写代码，所以需要：**一个我能直接点开使用的界面**，而不是命令行脚本。

---

## 1. 要交付的成果（Definition of Done）

1. 一个可以在我电脑本地启动的小程序，启动后自动打开浏览器界面（localhost 网页即可，
   不需要打包成 exe，只要"双击一个脚本/点一下"就能跑起来）。
2. 界面至少要有三块功能：
   - **监控列表管理**：显示我配置的所有"监控目标页面"，每条包括：学校/学院名称、
     页面用途（如"硕士拟录取名单""推免名额公示"）、URL、上次检查时间、当前状态
     （有更新 / 无更新 / 抓取失败）。
   - **更新提醒 / 变更记录**：当某个页面内容较上次抓取发生变化时，在界面里高亮显示，
     并展示"新增了哪些条目"（标题+日期+链接），而不是让我重新去对比全文。
   - **我的笔记区**：针对每条监控目标或每次更新，我可以手动输入结构化信息（比如
     "华南理工 2026 推免名额：XX人，来源链接：xxx，记录时间：xxx"），程序负责保存和
     按学校/年份分类展示，支持以后检索。
3. 一份**历史归档**：每次检测到页面更新，把当时的原始 HTML/纯文本自动存一份到本地
   文件夹（按"学校/日期"命名），防止官网页面被覆盖后再也找不回。
4. 程序需要能**定期自动检查**（比如每天一次，或我手动点"立即检查全部"按钮触发），
   不需要我一直开着电脑挂机——用 Windows/macOS 的计划任务或者我手动运行都可以，两种
   方式都在说明文档里写清楚。

## 2. 技术方案（建议，可按实际情况调整并说明理由）

- **语言**：Python（我熟悉度低，所以代码要有清晰注释，函数拆分要合理，不要写成一个
  几百行的大文件）。
- **抓取方式**：`requests` + `BeautifulSoup` 做静态页面解析即可，**不需要**处理反爬、
  不需要模拟登录、不需要处理动态 JS 渲染页面（见下方"选定的监控源"，都是静态列表页）。
  如果发现某个目标页面是 JS 渲染的，就跳过或告诉我改用手动记录，不要引入 Selenium 之
  类的重型方案。
- **数据存储**：本地 SQLite 或者干脆用结构化的 JSON/Markdown 文件都可以，Codex 自行
  判断，优先选**我以后自己也能直接打开、看懂、甚至手动改的格式**（这点比"技术上优雅"
  更重要）。
- **界面**：用 **Flask/FastAPI 起一个本地网页服务 + 简单前端**（不用框架也行，纯
  HTML+一点JS），我在浏览器里打开 `http://localhost:xxxx` 使用。不需要账号登录、不需要
  部署到公网。
- **定时检查**：提供两种方式并在 README 写清楚：
  1. 程序里内置一个"立即检查"按钮（我手动点）；
  2. 提供一个可选的操作系统计划任务配置说明（Windows 用"任务计划程序"，我目前用的是
     ____待Codex询问我的操作系统____，具体见下方"待确认信息"）。

## 4. 对 Codex 的具体执行步骤要求

1. 先写一个最小可用版本（MVP）：只做"抓取南昌大学化院一个页面 → 存档 → 网页界面里能
   看到列表和更新提醒"，跑通整条链路，让我先看到效果、提反馈，再扩展到其他学校。
2. **不要**一次性把所有学校的解析代码都写完再给我看——分阶段交付。
3. 每新增一个监控源，都要先实际请求该 URL 确认页面结构（列表容器的 HTML 标签、class
   名等），把解析器写成"每个来源一个独立的小函数"，方便以后某个学校网站改版了，我或
   Codex 只需要改那一个函数，不影响其他部分。
4. 代码和数据都放在下面第 5 节的目录结构里，**不要**散落在别处。
5. 交付时附一份 `README.md`，用简单中文说明：
   - 怎么安装依赖（`pip install -r requirements.txt` 之类）；
   - 怎么启动程序（具体到复制粘贴就能跑的命令）；
   - 怎么添加新的监控目标（因为以后我肯定会陆续发现新的学校页面要加进来）；
   - 怎么设置定时自动检查（对应我的操作系统）。

## 7. 明确不做的事（避免范围蔓延）

- 不做任何形式的登录/模拟登录抓取需要账号密码的内部系统。
- 不做验证码识别、不绕过反爬机制。对于抓取失败的页面，程序应记录"抓取失败，请手动
  查看"，而不是想办法硬突破。
- 不做自动判断"这条信息对我是否重要"的智能分析——更新提醒只做"内容变化检测"，语义
  层面的判断（比如这是不是化工相关、名额是涨是跌）由我自己看。
- 不追求界面美观度，能用、清楚、我能看懂状态即可。
