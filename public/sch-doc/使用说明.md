> **2026-09-17 架构变更：以下旧版云端操作已停止适用。** 新版在本机运行，GitHub 只做版本同步。工作流已移除定时采集及云端数据库写入步骤；本站保留历史公开资料。请使用仓库 `sch-doc-local/` 中的 `启动助手.cmd`，在本地页面添加学校、试抓确认、采集和管理笔记。设置中的“准备同步文件”将代码、来源配置和结构化记录复制到 Git 目录，不自动提交、推送或发布。原始附件及 SQLite 留在本机。完整新版说明见 `sch-doc-local/本地升级说明.md`。下文保留为历史使用记录，其中定时、手动云端采集及 GitHub 编辑来源流程不再使用。

## 直接使用

- 打开网页，无需Python、插件或账号即可查询公开资料。
- 首批研究笔记：按学校、年份、专业代码查询，导出当前结果为CSV。
- 通知与变更：查看已发现的通知和修改记录；发布日期与发现日期分别保留。
- 原件归档：下载真正保存成功的文件、纯文本及来源校验记录。HTML原文以安全的文本文件下载；需要还原时去掉文件名末尾 `.download.txt`。
- 监控来源：查看每个入口的实际成功/失败状态；失败不代表官网没有公告。
- 我的笔记：新增或编辑个人记录。内容只保存在当前浏览器，不会上传至GitHub。清理浏览器数据会删除笔记，换设备前务必导出JSON备份。
- 导入备份：支持网页版笔记备份和本地Python助手导出的完整JSON中的notes数组。导入的记录保存在“我的笔记”，不改变公开研究集。

## 自动采集与立即检查

GitHub Actions每天北京时间09:23、21:23触发，按来源间隔执行；手动运行时会检查所有启用列表。它在GitHub的电脑上运行，不要求你的电脑开机。定时任务可能排队延迟，长期没有仓库活动时也可能被GitHub停用；网页超过36小时没有新检查会提示。

“刷新云端资料”只读取最近发布的结果。需要立即抓取时：

1. 点击“打开云端检查任务”。
2. 登录你自己的GitHub，打开 `Build and deploy 162383.xyz`。
3. 点击 `Run workflow`，选择 `main`，再点击绿色的运行按钮。
4. 等待任务完成，再回来刷新。到“监控来源”核对结果，工作流绿色不等于每个高校都成功。

每个文件最多25MB，单轮最多25个详情/附件，失败与剩余队列留到后续执行。部分学校的robots、认证系统、验证码、动态页面或境外网络限制可能导致采集失败。需要登录的材料仍由你在正常浏览器保存，本地助手可以导入文件。

## 添加或修改来源

在“监控来源”点击“在GitHub编辑采集来源”，编辑 `scripts/sch_doc/sources/presets.json`。复制现有对象，填写官方网址、名称、类型及间隔，再提交至main。文件是JSON：英文双引号、对象之间加逗号；`enabled: 1`启用，`0`暂停。删除的配置下次运行会暂停对应旧来源，历史资料保留。

不会在网页中存放GitHub令牌。普通访客不能更改你的云端采集配置；仓库所有者通过GitHub的登录与权限完成编辑。

## 数据保存与备份

公开研究笔记来自 `scripts/sch_doc/seed_notes.json`。公开资料和采集历史保存在仓库独立的 **sch-doc-data** 分支，网页每次构建从该分支恢复，然后检查并保存新版本。分支未能读取时任务停止，避免用空库覆盖历史。

云端数据库和公开原件会发布到公开仓库及网站。个人浏览器笔记与原本地项目的私人数据库不在上传范围内。需要云端离线备份时，在GitHub切换到sch-doc-data分支，选择Code → Download ZIP；浏览器笔记另行导出。

归档会持续占用仓库和Pages容量。脚本对远端压缩备份设置512MB读取上限、1GB解压上限；到限后会停止并保留已有数据，需要维护存储。它是重点院校的公开资料工具，不能替代全国招生数据库。
